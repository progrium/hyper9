# h86: h9's 386 CPU

This describes h86 as built. h86 is a user-mode 386 CPU in Zig, modeled on v86's interpreter and JIT, that runs 9front's and Linux's 32-bit x86 programs. It's the browser host's only CPU, where it replaced v86, and the emulator's CPU for 386 binaries on native hosts in a `-Demu=hcpu` build. What it shares with ha64 (the emulator backend, the TLB, the IR, the emitters, and the code cache) is in [jit.md](jit.md); why it exists is in the [hcpu](../design/hcpu.md) proposal.

## Scope

- **A ring-3 process in protected mode with flat segments.** CS, DS, ES, and SS have base 0 whatever selector they hold, and their override prefixes change nothing. FS and GS have a base from the selector table below. There's no real mode, paging, descriptor table, task switch, interrupt delivery, or I/O.
- **Instructions:** every user-level integer instruction through the Pentium Pro (including `CMOVcc`, `CMPXCHG8B`, `BSWAP`, `XADD`, and `CPUID`), string instructions with `REP`, x87, MMX, SSE, and SSE2, at both operand sizes and with 16-bit addressing. That's what h9's `AT_HWCAP` for i386 advertises.
- **Everything else faults.** Privileged instructions, port I/O, far transfers, `IRET`, `SYSENTER`, and `INT` with a vector other than 64 or 0x80 raise #GP, as at ring 3 with IOPL 0. An encoding the table doesn't list raises #UD, never a wrong result.

**CPUID** reports "GenuineIntel", as v86 does, family 6, one logical processor, and EDX `0x078bfbff` (FPU, TSC, CX8, CMOV, MMX, FXSR, SSE, and SSE2 among them), with no SSE3 or later, no AVX, and no OSXSAVE. The brand string is "h86 386 interpreter". Programs that pick code paths at run time from CPUID, as OpenSSL and Go's runtime do, stay on SSE2.

**RDTSC** returns instructions retired, so it moves forward and two runs of a program see the same values.

**Selectors.** A small table stands in for the GDT: the null selector, 9front's user code and data selectors (`0x23` and `0x1b`, pc/mem.h's UESEL and UDSEL), and Linux's TLS entry 6 (`0x33`), whose base is `X86Extra.tls`, as `set_thread_area` sets it. Loading anything else into a segment register, or an SS selector whose RPL isn't 3, raises #GP. A segment holding the null selector faults on use.

## State

`src/interp/x86/cpu.zig`'s `Cpu`:

| Field | What |
| --- | --- |
| `r` | EAX, ECX, EDX, EBX, ESP, EBP, ESI, and EDI, in encoding order |
| `eip` | |
| `fl` | EFLAGS: the materialized `bits`, and the `lazy` record of the last flag-setting operation ([Flags](#flags)) |
| `seg`, `seg_base`, `seg_null` | The six selectors, their bases, and which hold the null selector |
| `tls` | The base of Linux's TLS segment |
| `fpu` | The x87: eight 80-bit registers by physical number, TOP, the control word (FNINIT's `0x037f`), the status word, the abridged tag word, and the last opcode and instruction and operand pointers |
| `xmm`, `mxcsr` | Eight XMM registers, and MXCSR (`0x1f80`) |
| `trap`, `ecode` | Ureg.trap and Ureg.ecode, as the last exit left them |
| `retired` | Guest instructions retired |

`getUreg` and `setUreg` copy the general registers, EIP, EFLAGS (materialized), the selectors, `trap`, and `ecode` to and from 9front's 386 Ureg; a selector the table doesn't hold is replaced by the null selector. `getExtra` and `setExtra` copy the FXSAVE image field for field (with ST0 to ST7 in stack order, and TOP in the status word) and the TLS base, with none of the per-register assembly Unicorn needs; the last-instruction fields, which Unicorn leaves zero, are filled.

## Exits

| Exit | When | Ureg.trap, ecode | EIP |
| --- | --- | --- | --- |
| `.syscall` | `INT $64` (9front) or `INT 0x80` (Linux) | 64 or 0x80 | Past it |
| `.breakpoint` | `INT3` | 3 | Past it |
| `.fault`, with the address and access | A page fault: unmapped, or without the permission | 14; `4`, or `6` for a write | At the instruction |
| `.fault`, with the vector as the syndrome | #DE 0, #OF 4 (`INTO`), #BR 5 (`BOUND`), #UD 6, #GP 13, #MF 16, or #XM 19 | The vector; 0 | At the instruction, or past it for `INTO` |

Every exception is precise: a faulting instruction leaves the registers as they were before it, with EIP at it, so the kernel can fix the fault (grow the stack, fill a page) and run it again. Memory may already hold what an earlier part of it wrote (`PUSHA`, `ENTER`), which a rerun writes again. An instruction that runs onto an unmapped or non-executable page faults at its first byte with the second page's address as the fault address.

## Decoding

`src/interp/x86/table.zig` is the encoding table: every encoding a ring-3 program can use, as a comptime array in the shape of v86's `gen/x86_table.js`. An entry says how the instruction is encoded (ModRM, immediates, operand size), what it does, which operands it reads and writes, which fixed registers it uses, and whether it ends a block. x87 (D8 to DF) and MMX, SSE, and SSE2 (most of 0F) are listed with enough to find their length, as `.x87` and `.sse`, with their semantics keyed by opcode, prefix, and ModRM in their own files.

One table gives the decoder, T0's dispatch, and the lifter, each of which looks an opcode up instead of having its own switch over the opcode map. v86 generates Rust from JavaScript at build time to get the same; here there's no generator and no generated file.

`src/interp/x86/decode.zig` turns bytes into an `Inst`: prefixes, opcode, ModRM, SIB, displacement, and immediates, up to the architectural limit of 15 bytes. It never touches guest memory: an instruction that runs off the end of the bytes it was given says so with `Truncated`, and the caller faults at the right address. `effects` gives an instruction's register, flag, and memory read and write sets, for the lifter's liveness analyses.

## T0

`src/interp/x86/exec.zig` runs one instruction at a time, through a handler per table entry. Guest memory is reached through `translate`, which gives the host address of a guest address, valid to the end of its page, or null for a page fault; an access that crosses a page translates both pages before it touches either. In the vmm backend that's the vCPU's TLB (`src/interp/x86/tlb.zig`), with hits inlined and `mem.probe` on a miss.

**Decode caches.** Variable-length code can't be predecoded a page at a time, since a page has no fixed instruction boundaries and a jump can land anywhere, so T0 caches decoded instructions as they're reached:

- `PageCache` maps each offset of a page to the instruction decoded there, so a fetch on the page the last one was on is an index, with no translation or hash. A page holds while its host page is the same, and the whole cache goes when code is invalidated (`CodePages`' epoch moves).
- `ICache` holds 16,384 instructions direct-mapped by address, for instructions that cross a page and memories that don't track code; there, a hit is used only if memory still holds the bytes it was decoded from.

**REP string instructions** retire an iteration at a time, so a fault or a stop in the middle leaves ECX, ESI, and EDI exact and the instruction restartable.

**Stops.** T0 checks the exit request and the budget between instructions, and can stop after a given number of taken branches, which the web host's T1 uses.

## Flags

EFLAGS' arithmetic flags are lazy in T0, as in v86 and QEMU (`src/interp/x86/flags.zig`): a flag-setting instruction records its kind, operand size, operands, and result, and a flag is computed only when something reads it. While the record's kind isn't `.none`, CF, PF, AF, ZF, SF, and OF in `bits` are stale; DF and the rest are always current. Most flag results are overwritten unread, so most are never computed.

Undefined flags follow QEMU, and so Unicorn, so lockstep compares all six: AF is 0 after logic operations, shifts, and multiplies; SF, ZF, and PF after a multiply come from the low half of the result; and OF after a shift of more than one bit is computed as for one bit.

## x87

`src/interp/x86/x87.zig` runs every D8 to DF instruction and `FWAIT`.

- **Arithmetic is software:** `f80.zig` is a Zig port of the `extF80` functions of Berkeley SoftFloat 3e (BSD-3) with the 8086 specialization, covering what v86 takes from SoftFloat: add, sub, mul, div, rem, sqrt, round to integer, the comparisons, and conversions to and from i32, i64, f32, and f64. It matches SoftFloat bit for bit, checked against TestFloat's vectors. Rounding mode, precision control, and the exception flags are per call, in an `Env` made from the control word, so every vCPU's state is its own and the `fldcw; fistp; fldcw` truncation idiom works.
- **The rest** is `x87math.zig`: FPREM and FPREM1 in exact integer arithmetic, and FSIN, FCOS, FSINCOS, FPTAN, FPATAN, F2XM1, FYL2X, FYL2XP1, FSCALE, and FXTRACT in binary128 rounded once to 80 bits. The transcendentals reduce by the x87's approximation of pi, as the hardware does, and are within an ulp or so of it, not bit for bit.
- **Exceptions** set their flag in the status word. A masked one takes the x87's default response. An unmasked one also sets ES and B, and the next waiting instruction raises #MF instead of running. Unmasked IE, DE, and ZE leave the destination and the stack as they were; unmasked OE and UE write the masked response rather than the hardware's exponent-wrapped one, which only a handler reading the result could see.
- **C1** is set when a result was rounded up and on a stack overflow, and cleared on an underflow, as on the hardware.

Results are the same bits on every host and in wasm. 9front's 8c uses the x87 for every `float` and `double`, so 9front's 386 programs depend on it.

## MMX, SSE, and SSE2

`src/interp/x86/sse.zig` runs every `.sse` table entry (0F 10 to 17, 28 to 2F, 50 to 7F, C2 to C6, D0 to FF, and 0F AE's FXSAVE, FXRSTOR, LDMXCSR, and STMXCSR).

- **MMX registers are the x87's:** MMi is the significand of physical register i, and writing one sets its exponent to all ones. Every MMX instruction first raises #MF for a pending x87 exception, then sets TOP to 0 and tags every register valid; `EMMS` tags them all empty.
- **Floating point** goes through `src/interp/softfloat.zig` with x86's rules: MXCSR's rounding, DAZ, FTZ, and sticky flags, the negative default NaN, the first NaN operand's NaN, and x86's MIN, MAX, and conversion results. An unmasked exception raises #XM with the destination as it was and the flags set in MXCSR.
- **128-bit memory operands** must be 16-byte aligned, or #GP, except for MOVUPS, MOVUPD, and MOVDQU.

## T1

h86's front end is `src/jit/x86/`, on the shared layer in [jit.md](jit.md). T1 is the default on x86-64 and arm64 hosts and on the web.

**Lifted** (`lift.zig`): moves, the ALU and its flags, shifts by a constant or CL, rotates, the multiplies, `DIV` and `IDIV` of a register with the #DE checks inline (a zero divisor, and a quotient that doesn't fit), the stack (`PUSH`, `POP`, `LEAVE`, `CALL`, and `RET`), direct and indirect branches, `LOOP` and `JECXZ`, `SETcc`, `CMOVcc`, the atomics (`XCHG`, `XADD`, `CMPXCHG`, and `CMPXCHG8B`, as `cas`), x87 through helpers, the common SSE and SSE2 forms, and `REP` string instructions. Everything else (MMX, 16-bit addressing, and the rarer encodings) runs through `call.interp`, which hands the instruction to T0.

**Regions** are a linear scan from the entry that goes on through conditional branches and stops after any other unconditional transfer, after an instruction only T0 can end (`INT`, a far or 16-bit transfer, anything that traps), or at the limits: 512 instructions over at most two pages. Branch targets inside the scanned range start blocks, and a backward one is a loop, with a `poll` at its head.

**Position-independent code.** `call next; pop r` is lifted as a constant load, and a call to a thunk that is `mov r, [esp]; ret` as setting r to the return address, without the call or the return.

**Guest state** is exact wherever a region can leave: every lifted instruction does its loads and stores before it writes a register or the flags, the flags are written back before every load, store, call, and exit, and a read-modify-write's load is marked `rmw`, so it faults as the write it is.

**Flags** (`flags.zig`) are `eflags.*` values in the IR. Within a block the lifter holds the current flags as a value and writes it back only before something that can leave the region or at the end of the block, and flags nothing reads before the next writer are never computed, found from `decode.effects`. Where the host's emitter lowers lazy records (`pending.flags` with aux2 = 2, on all three), a region writes T0's `lazy` record instead of materializing `bits`, as T0 would, so flags that cross a region exit are still computed only when read.

**x87** (`helpers.zig`): each x87 instruction is a `call.helper` that runs `x87.zig` on the Cpu, with the operand's linear address worked out in the IR. A memory operand is translated (both pages if it crosses) before anything is written. If the instruction traps (a pending exception, #UD, or a page fault), the helper puts back everything it changed and the region's guard runs it on T0 through `call.interp`, which raises it. Data movement and arithmetic with a memory operand have a fast helper that does the work when it's exact and nothing is raised. `FNSTSW AX`, which doesn't wait, needs no guard, so `FCOM; FNSTSW AX; SAHF; Jcc` stays in the region.

**SSE and SSE2** lift to the IR's `fp.*` and `v.*` ops for scalar single and double arithmetic, moves, conversions, and compares, and the 128-bit moves and logic. MMX forms stay on T0.

**REP string instructions** run a page at a time through `call.interp`, with a `poll` between pages, so ECX, ESI, and EDI are exact at any stop.

**TSO.** Every region sets `Region.tso`, so on arm64 hosts loads are load-acquires and stores store-releases ([jit.md](jit.md), Concurrency).

## Memory order

x86 is TSO. T0 does aligned loads as acquires and aligned stores as releases, `LOCK`-prefixed instructions and `XCHG` with memory as host atomics, and `MFENCE`, `LFENCE`, and `SFENCE` as a full barrier. T1 keeps the same order with `Region.tso` on arm64 hosts, and has it from the hardware on x86-64 hosts. `LOCK CMPXCHG` and `CMPXCHG8B` are `cas`.

## The browser host

On the web h86 is the only backend, `src/vmm/h86.zig` through `hcpu`, compiled into `h9.wasm` itself, and `--backend v86` is an alias of `emu`. There's no guest kernel: v86's shim, its GDT, IDT, TSS, page tables, and real-mode start, the pinned register offsets, `v86.wasm`, and its instantiation order are gone. A system call is a return from `run`.

T1 there is `src/jit/wasm_t1.zig` with the wasm emitter: blocks are counted, hot ones lifted after a vCPU's first 2M instructions, and batched into modules that `h9-web.js` compiles asynchronously into h9's function table, while T0 runs ([jit.md](jit.md), The web host). Preemption is the budget: 64K instructions at a time, yielding to the event loop every 2 ms.

The download is `h9.wasm` alone, 3.68 MB (894 KB gzipped), against 3.82 MB for `h9.wasm` and `v86.wasm` before. `zig build integration -Dweb` gives the same counts as v86 did (214 pass, 2 fail, and 156 skip, with the same 2 failures), and on the speed rounds awk took 7.00 s against v86's 6.66 s and md5 0.79 s against 0.82 s.

## Testing

- **Unit tests** in each file, including T0's against hand-assembled programs, `f80.zig` against a sample of TestFloat's vectors (`scripts/testfloat.sh` runs them all), and `softfloat.zig` likewise.
- **The region check** (`src/jit/check/x86.zig`): every lifted path, by hand-written programs and by `fuzz-x86`'s generator, against T0 from the same state ([jit.md](jit.md), Testing).
- **`zig build fuzz-x86`:** random valid sequences (`src/jit/check/gen_x86.zig`) run on T0 and T1 a region at a time, and against Unicorn in lockstep with `-Demu=unicorn`.
- **`zig build litmus-x86`:** store buffering with and without a locked instruction between the store and the load, message passing, and a `LOCK XADD` counter, on compiled code. Plain store buffering may see both loads 0; the others must never show a non-TSO result.
- **`zig build x86-jit`** runs the `[x86-jit]` cases in `tests/x86.zig` on T0 and T1: a `DIV` by zero gives vector 0 at the `DIV`; `fistp` truncates under RC=chop; x87 results are the same bits on every host; a `REP MOVSB` stopped by a fault, or between iterations, resumes exactly; a store into the executing page takes effect at the next instruction; an instruction crossing into an unmapped page faults at its first byte; an unknown GS selector raises #GP; CPUID reports SSE2 and no AVX; and four `LOCK XADD` threads lose nothing.
- **`zig build integration -Darch=386 -Demu=hcpu`** and **`-Dweb`** run the integration suite on h86, and `-Djit-check` checks every region it compiles.
- **`zig build x86-inventory`** reports the 386 instructions in binaries, for choosing what to lift next.
