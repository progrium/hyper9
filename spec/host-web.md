## Web host (`web`)

`zig build web` builds h9 for wasm32-wasi into `zig-out/web/` ([browser-host](../design/epoch-0/browser-host.md)). The kernel, the machine, and the CLI are the same code; what differs is underneath them. Native hosts are unchanged.

| Piece | Web host |
| --- | --- |
| Threads | One executor ([scheduler](../design/scheduler.md), `src/kern/sched/web.zig`): each kernel process, and each of h9's own threads (`web.Thread`, `src/web/task.zig`), is a task, a continuation with its own shadow stack, switched with Binaryen's Asyncify (`zig build web` runs `wasm-opt --asyncify` on the module, leaving out the CPUs and the JIT, which never park). The executor's loop runs at the bottom of `_start`, the one `promising` export; when nothing is runnable, and every 10 ms otherwise, it calls `idle`, the one `Suspending` import, which comes back when a timer is due or the JS host has finished ops. An op is an import that waits on JavaScript (the console read, the signal wait, `gfx_wait`, and the WebSocket and port waits): it returns an id at once, and the task parks in `h9_task_await` until `idle` hands back the result. A switch saves and restores what's per thread natively: `errno`, h9's Zig threadlocals, and drawterm's `up`. setjmp and longjmp stay wasm exception handling, which Asyncify passes through, since no task parks inside a handler. |
| OS layer | `src/kern/os-wasm.c` instead of `posix.c`: `procsleep` and `procwakeup` park and unpark, `osyield` yields to the other tasks, timers park with a timeout, and `devip-wasm.c` stubs the sockets. |
| Stacks | wasm has no guard pages, so each stack has a canary at its low end, below which is the task's 32 KiB Asyncify buffer, and every switch also checks the stack pointer against it; either failing panics the machine with the task's name. Kernel processes and h9's own tasks get 320 KiB, `main` 1 MiB. Stacks go on a free list when their task ends. |
| `std.Io` | `src/web/io.zig`: std's single-threaded implementation over WASI, with futex waits and sleeps that park. 64-bit atomics become plain values (`web.Atomic`), since wasm32 has no 64-bit atomic RMW. |
| Files | WASI. Under Node, `h9-node` preopens `/`, so roots and `--cwd` are real host directories, resolved with readlink one component at a time since WASI has no realpath. In the browser, `src/web/wasi-mem.js` serves a read-only tree from `root.h9a`, which `tools/webroot.zig` packs from the 386 root and `src/web/root.list`. WASI has no permission bits, so `#U` (devfs, wrapped in `src/kern/devtab.c`) gives files and directories `rwxrwxr-x`; the policy, not the mode, decides access. |
| Console | `src/web/cli.zig`: stdin, interrupt, hangup, and raw mode are imports the JS host serves, from Node's process or from the page's messages. |
| Policy | `#C` and `#I` are always masked. The network is WebSockets only: `--net=outbound` (the default) and `enable` bind `#ℏ` alone at `/net`, and `disable` masks it. |
| WebSockets | `hstream.zig`'s web branch calls `h9-web.js`'s `h9_ws_*` imports, over the runtime's `WebSocket` ([websocket-9p](../design/epoch-0/websocket-9p.md)): `ws_open` and `ws_send` return at once (`ws_open`'s last argument asks for a static tree when an `http(s)` mount's server doesn't upgrade; see [Static trees](ninep.md#static-trees)), `ws_opened` and `ws_recv` are ops, and a stream's reader is a task parked in `ws_recv`, which hands over as many queued binary messages as fit. The browser does the handshake, TLS, proxies, and pongs, so `--root-header`, `--root-ca`, and `header` in `ctl` are errors, there's no keepalive, and a failed connection says only "connection failed". In place of running a `--cred` helper, the web branch calls the embedder's `credentials(url, failed, helper)` through the `ws_cred` op, before each host-made handshake, with `helper` the matching `--cred` command's words or undefined. It answers with header lines, which only Node's `WebSocket` can send (`ws_open` refuses them elsewhere), or a `url URL` line to connect to instead, and the open is tried once more after a failure, with "connection failed" as `failed`. `h9-node`'s callback runs the helper as native h9 does. A page's `WebSocket` shows no response headers, so `9P-Uid` and `9P-User` aren't read. `--net-allow` checks a connect's name or literal address but can't check what a name resolves to, which the plan lists as a caveat. |
| Ports | `h9-web.js`'s `Ports` holds a machine's `MessagePort`s by name ([port-streams](../design/epoch-0/port-streams.md)). `port_open(name)` puts a port in the WebSockets' table at once, or returns -1 for no such port, -2 for one in use, and -3 for one opened and closed; from there `ws_recv`, `ws_send`, `ws_close`, `ws_status`, and `ws_free` take it as a socket. Each message is one 9P message, an `ArrayBuffer` transferred on send; on receipt any `ArrayBuffer` or typed array is appended to the stream. `null` from the other end, or the port's `close` event where the runtime fires one (Node does), ends the stream, and a message that isn't binary closes it, posting `null`, as does h9's hangup. `port_accept`, an op, hands h9 each port the page serves the machine on, until `port_stop`; `port_serving` says whether the embedder serves (with `/net`), which sets `Machine.Options.serve_ports` and `serve_net`, and the machine forks its server Proc with no listener. `h9-node` takes ports from the module `H9_NODE_PORTS` names, called with the `Ports` before the machine starts. |

### The 386 CPU on the web

Web builds run 386 binaries on h9's own CPU, h86 (`src/engine/hcpu/h86.zig`, through `src/engine/hcpu/engine.zig`), the only engine there; `--engine v86`, the name of the v86 backend it replaced, is an alias of `hcpu` for one release, as `emu` is. Guest memory is an arena grown with `memory.grow` in h9's own linear memory (`src/engine/arena.zig`), 256 MiB by default.

T0 interprets; T1 (`src/engine/hcpu/jit/wasm_t1.zig`) counts entries to blocks and, once a vCPU has retired 2M instructions, lifts hot ones, batches them into a module (`src/engine/hcpu/jit/emit/wasm.zig`, a function per region, with chain cells and a jump-cache lookup for indirect branches), and has `h9-web.js` compile it asynchronously into table slots of h9's own function table; T0 runs until the batch is installed. `CodePages`' invalidation drops a page's regions and their slots.

Preemption is a budget: each slice runs 64K instructions at a time, and `run` yields to the event loop once 2 ms have passed since the last yield, returning `.interrupted`; a Linux `sched_yield` is the kernel's `sleep(0)`, a task switch here.

### Hosts

`h9-node` runs the CLI under Node 24 or later, with the same flags as `h9`; it's how the integration suite tests the web host.

In a page, `createMachine({ mounts, binds, memory, policy, terminal, gfx })` from `h9-web.js` starts one machine in its own Worker (`src/web/worker.js`) and `machine.run(argv)` resolves to the exit status. `mounts` takes the CLI's mount flags as strings (`'--archive=stack.h9a:/'`) or objects (`{ archive }`, `{ url }`, `{ dir }`, `{ builtin }`, or `{ tmp }`, with `dst`, `opts`, and `up: true` for the `up` option), and defaults to `root.h9a` on `/`; each archive is fetched and unpacked into the Worker's tree, and `binds` are `--bind` lines. A `{ url }` that's `http://` or `https://` and whose server doesn't upgrade is served as a static dotfs tree by `src/web/statictree.js`, a 9P2000 server over the page's `fetch` behind the WebSocket the kernel opened. `gfx` gives it a canvas ([Graphics](machine.md#graphics---gfx)). `ports` (names to `MessagePort`s) and `serve` (`true`, a port, or a list, with `serveNet`) go to the Worker with `start`, transferred, and `machine.addPort`, `removePort`, and `serve` send them later; a mount `{ port }` is `--url port://NAME`, a `MessagePort` given directly being added under the next free `mountN`. With `up`, a port mount is an up layer the page keeps: the page serves a writable 9P tree on the port and stores it as it likes, and the same tree mounts again without `up`.

`root` is a root archive's URL, or a `ws://` or `wss://` URL of a 9P server, under which WASI sees an empty tree; the page edits and echoes lines in cooked mode, passes keys in raw mode, and sends the interrupt key as `Machine.Signals.interrupt`.

The demo page (`index.html`) runs an interactive rc, over `?root=` when given, or with `?rio`, rio and acme on a canvas.
